工具的作用是帮助你更稳定、更清楚地完成学习任务。刚开始时，不需要安装大量软件或追求复杂配置。先掌握少数常用工具，并理解它们分别解决什么问题。

## VS Code：编辑代码和文档

Visual Studio Code，简称 VS Code，是一个代码编辑器。它可以用来编写程序、Markdown 文档和项目配置文件。

开始使用时，先掌握这些基本操作：

- 打开一个完整文件夹，而不只是打开单个文件。
- 使用左侧文件树创建、重命名和查找文件。
- 使用全局搜索查找项目中的文字。
- 打开集成终端并运行课程或项目命令。
- 根据正在学习的语言安装必要的扩展。

扩展并不是越多越好。只安装课程明确要求或当前确实需要的扩展，可以减少配置冲突。

## Markdown：整理结构化笔记

Markdown 是一种轻量级标记语言。它使用少量符号表示标题、列表、链接和代码块，适合编写学习笔记、项目说明和技术文档。

常用语法包括：

```markdown
# 一级标题

## 二级标题

- 列表项目
- 另一个项目

[链接文字](https://example.com)

`行内代码`
```

Markdown 文件通常以 `.md` 结尾。它保存的是纯文本，因此容易搜索、修改和使用 Git 管理。

## 终端：通过命令操作工具

终端提供了一种通过文字命令操作电脑的方式。许多开发工具没有完整的图形界面，需要在终端中启动。

常见操作包括：

- 进入某个文件夹。
- 查看当前目录中的文件。
- 运行程序或项目命令。
- 查看工具版本和错误信息。

使用终端时，先确认自己位于哪个目录，再执行命令。不要复制执行自己无法判断作用的删除、覆盖或系统配置命令。

## Git：记录文件版本

Git 是版本控制工具，用来记录文件随时间发生的变化。它可以帮助你：

- 查看哪些文件被修改。
- 保存一个带说明的版本快照。
- 对比不同版本的内容。
- 在出现问题时找到较早的记录。
- 与其他成员协作修改同一个项目。

初学阶段先认识下面几个操作：

```text
git status   查看当前改动
git add      选择要放入下一次记录的改动
git commit   保存一个本地版本快照
git push     将本地提交上传到远程仓库
git pull     获取远程仓库中的新提交
```

Git 不等于 GitHub。即使没有网络，Git 仍然可以在本地记录版本。

## GitHub：保存和协作远程项目

GitHub 是托管 Git 仓库的在线平台。它可以保存远程副本，并提供 Issue、Pull Request 和代码审查等协作功能。

- Issue：记录问题、建议和待办事项。
- Pull Request：提出一组代码修改并请求合并。
- Repository：保存项目代码、文档和版本历史的仓库。

不要把密码、令牌、个人隐私或其他敏感信息上传到公开仓库。

## 工具之间如何配合

这些工具并不是互相替代的：

```text
VS Code
→ 编辑代码和 Markdown

终端
→ 运行程序和开发命令

Git
→ 记录本地版本

GitHub
→ 保存远程副本并支持协作
```

例如，完成一次项目修改时可能经历：

```text
用 VS Code 修改文件
→ 在终端中运行检查
→ 用 Git 保存版本
→ 将提交推送到 GitHub
```

## 推荐的学习顺序

1. 先学会在 VS Code 中打开文件夹、编辑和搜索文件。
2. 学会使用 Markdown 编写结构清楚的笔记。
3. 认识终端、路径和运行命令的基本方式。
4. 在自己的练习项目中使用 Git 记录版本。
5. 最后再学习 GitHub 协作流程。

工具只有在反复使用中才能熟悉。遇到不理解的命令时，先查清它会读取、创建、修改还是删除什么，再决定是否执行。
