# Sprint 0 Review 与学习回顾

## 本轮目标

把一个模糊的“科协门户网站”想法，转化为可以开始开发的产品需求、页面结构、技术架构和工程骨架。

## 本轮交付

- 确认网站服务于武汉科技大学人工智能与自动化学院科协。
- 确认第一版是一个无需登录的公开主页。
- 确认竞赛平台是独立项目，门户只提供入口。
- 建立产品愿景、Product Backlog 和主页验收标准。
- 完成主页信息架构、用户流程与低保真线框图。
- 确认黑白双主题、反色导航和少量蓝色点缀的设计方向。
- 选择 Astro 静态架构，暂不建设后端、数据库和管理后台。
- 建立可运行、可检查、可构建的项目骨架。
- 整理项目目录并建立 Git 仓库。
- 创建并推送 `sprint-0` 分支。

## 你目前需要理解的内容

### Scrum

- Sprint 是一个有明确目标和完成标准的短开发周期。
- Product Backlog 是整个产品的需求列表，Sprint Backlog 是本轮选中的任务。
- Sprint 结束不仅要展示成果，还要评审、学习和回顾过程。

目标程度：认识。

### MVP 与范围边界

- MVP 是能够验证核心价值的最小版本，不是“随便做一个很差的版本”。
- 暂时不做登录和后台，是为了避免尚未验证的复杂度。
- 竞赛平台与门户分开，可以避免两个项目的业务和数据互相污染。

目标程度：能够用自己的话解释。

### 静态网站

- 当前页面在开发者构建时生成 HTML、CSS 和 JavaScript。
- 学生访问时不需要连接应用后端或数据库。
- 内容更新后需要重新构建和部署。

目标程度：认识。

### Astro、TypeScript 与 CSS

- Astro 负责组织页面和组件，并生成静态网站。
- TypeScript 帮助提前发现内容字段和组件参数错误。
- CSS 控制布局和视觉；设计变量让深浅主题共享同一套组件。

目标程度：知道各自负责什么，不要求掌握语法。

### Git 与 GitHub

- Git 在本地记录版本历史。
- GitHub 保存远程副本并支持团队协作。
- 分支用于隔离一组工作；提交是一个有说明的版本快照；推送是把本地提交上传到远程。

目标程度：认识，并能在指导下使用。

## 最少必会操作

```bash
pnpm dev
pnpm check
pnpm build
git status
git branch --show-current
```

- `pnpm dev`：启动开发预览。
- `pnpm check`：运行 Astro 与 TypeScript 检查。
- `pnpm build`：生成可部署的静态网站。
- `git status`：查看当前有哪些未提交修改。
- `git branch --show-current`：查看所在分支。

## 本轮关键决策

- 使用 Astro 静态架构，因为第一版是内容型公开主页。
- 使用原生 CSS 变量实现主题，避免同时维护两套页面。
- 不引入数据库、登录、后台、状态管理和 UI 组件库。
- 新闻等内容先由开发者更新，真实发布需求出现后再考虑 CMS。

## Retrospective

### 做得好的地方

- 在编码前明确了产品边界、主页结构和验收标准。
- 没有为了未来可能出现的需求提前建设复杂后端。
- 技术选择形成了 ADR，后续可以追溯原因。
- 工程最终通过格式、类型和生产构建检查。

### 出现的问题

- 最初误把 `asaw` 当作项目子目录，说明路径约定应尽早明确。
- 开发环境缺少系统 Node.js 与 GitHub CLI，初始化耗时增加。
- pnpm 的语言服务器依赖出现兼容问题，需要锁定间接依赖版本。
- 部分长文件操作缺少及时反馈，造成了“卡死”的体验。

### Sprint 1 改进

- 开始任务前先检查环境和工作区状态。
- 把操作拆成更短、可观察的步骤。
- 每完成一个主页区块就立即检查桌面端、移动端和双主题。
- 每轮结束增加固定的学习回顾和知识检查。

## 当前结论

Sprint 0 的工程产出和学习回顾均已完成，Sprint 正式关闭。

Product Owner 已能够识别：

- Astro 用于组织源码并生成静态网站。
- `src/` 存放应当修改的源码。
- `dist/` 是工具生成的构建产物，不应直接修改。
- 当前网站只是开发占位页，正式主页属于 Sprint 1。

关闭日期：2026-08-16。
