# Sprint 2 Review 与学习回顾

> 工程验收、知识检查和 Retrospective 已完成，等待 Product Owner 确认关闭 Sprint 2。

## 本轮目标

建立面向新生和低年级学生的文档中心架构，使公开资料可以通过 Markdown 持续维护，并提供清晰的分类、阅读和搜索入口。

## 本轮交付

- 建立文档首页、分类页和任意层级的文档详情路由。
- 建立带字段校验的 Markdown 内容模型。
- 实现“简介”和“学习资料”同级的折叠式目录。
- 实现右侧页内跳转、面包屑及上一篇/下一篇导航。
- 完成 VS Code、Git/GitHub、CMake、容器和包管理器基础资料。
- 将当前公开资料接入静态搜索索引。
- 编写开发者新增和修改 Markdown 文档的维护说明。
- 完成 Astro 类型检查、Prettier 格式检查和生产构建。

## 概念地图

## 知识检查结果

Product Owner 已能够认识：

- Markdown 是文档源内容，Astro 负责读取并转换，布局组件提供统一网页结构。
- `src/content/docs/` 保存公开网站文档，项目根目录的 `docs/` 保存内部管理资料。
- `.astro/` 和 `dist/` 是工具生成内容，不作为日常修改入口。
- `draft: true` 表示草稿，不应生成公开页面。
- `astro dev` 用于开发预览，`astro build` 用于生成最终网站。
- 当前网站没有数据库；左侧目录和搜索条目仍有部分手工维护工作。

## Retrospective

### 做得好的地方

- 先确定文档层级和内容模型，再逐步补充具体内容。
- 通过 Markdown 降低后续成员维护公开资料的门槛。
- 根据实际阅读体验反复修正目录层级、页内跳转和页面布局。
- 收尾阶段补齐维护说明、导航和工程检查，没有只停留在可见页面。

### 出现的问题

- 文档内容边界和准确表述不容易一次确定，内容讨论占用较多时间。
- “总览”和“右侧页内跳转”曾发生理解偏差，引起一次不必要的返工。
- 右侧跳转曾因网格位置没有明确指定而落到错误位置。
- 当前搜索索引需要手动登记，新增 Markdown 后不能自动同步。
- 隐藏后台开发服务器的启动与生命周期仍不够直观。

### 后续改进

- 文档先发布短小、可靠的基础版本，再在集中内容整理 Sprint 中扩充和校对。
- 需求中明确区分“分类总览页”“左侧目录”和“右侧页内跳转”。
- 后续让目录和搜索索引从 Content Collections 自动生成，减少重复维护。
- 将操作系统、网络、文件系统和编译过程等稳定知识规划为独立“基础概念”分类；工具文档保留具体操作，两者交叉链接。
- 内容 Sprint 开始前先确定资料来源、目标读者和每篇文章要解决的单一问题。

## 转入 Product Backlog

- 自动从公开 Markdown 生成左侧目录和全站搜索索引。
- 建立“基础概念”分类，但不在本轮仓促编写具体内容。
- 后续集中校对并扩充已有学习资料。
- 正式域名上线后进行手机端阅读体验验收。

## 回顾结论

Sprint Goal 已达成。本轮建立了可扩展的文档中心骨架，并用多篇基础工具资料验证了内容模型、路由、导航和搜索流程。剩余问题属于后续自动化、内容建设和移动端验收，不阻塞本轮关闭。
