# Sprint 3：现有成果完善与公开部署

## 状态

进行中。开始日期：2026-08-18。

## Sprint Goal

在不扩张大型新功能的前提下，完善主页、文档中心和搜索等已有成果，并把只能通过本机开发服务器访问的网站部署为稳定的公网 HTTPS 网址。

## 用户价值

- 本校学生无需安装开发工具或打开终端，通过网址即可访问网站。
- 已有页面的内容、导航和搜索更加一致、可靠。
- 开发者向指定分支提交通过检查的代码后，网站可以自动构建和更新。

## 部署路线

第一阶段使用 GitHub Pages：

```text
本地源码
  ↓ Git commit / push
GitHub 仓库
  ↓ GitHub Actions 自动检查与构建
Astro 静态文件
  ↓ GitHub Pages 发布
公开 HTTPS 网址
```

预计临时网址：

```text
https://icewater721.github.io/automation-science-association-website/
```

正式域名作为第二阶段：先确认名称、预算和管理归属，再购买域名、配置 DNS 和 HTTPS。正式域名没有确定前，不阻塞 GitHub Pages 上线。

## 暂不纳入本轮

- 数据库、登录和内容管理后台
- 新闻、通知和活动系统
- 服务中心的正式业务功能
- 独立竞赛平台功能
- 大批量编写操作系统等基础概念资料
- 为部署静态网站购买云服务器

## Definition of Done

- 网站具有无需本地终端即可访问的公开 HTTPS 地址。
- GitHub 中的部署流程能从源码自动检查、构建和发布网站。
- 主页、文档、搜索、主题和主要站内链接在公网子路径下可用。
- 新增公开 Markdown 后，文档目录与搜索索引不再要求重复手工登记。
- 已有核心内容完成一轮准确性和一致性检查。
- 项目中记录部署方法、公开网址和后续更新流程。
- Astro 类型检查、Prettier 格式检查和生产构建成功。
- Sprint Review 和学习回顾完成。

## 风险与依赖

- GitHub Pages 需要在仓库设置中启用 GitHub Actions 发布源。
- 当前站内链接大量以 `/` 开头，部署到仓库子路径前必须统一处理。
- 自定义域名涉及费用、实名信息、续费和账号归属，需要 Product Owner 单独决定。
- 如果仓库或 GitHub Actions 权限受限，应先解决权限，不临时改用复杂服务器方案。
