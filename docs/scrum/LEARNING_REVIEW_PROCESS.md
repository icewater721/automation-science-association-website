# Sprint 学习回顾流程

## 目的

每个 Sprint 结束时，Product Owner 应能够理解本轮交付的功能、关键技术概念、项目结构和验证方法，但不要求立即深入框架内部或记住全部代码细节。

学习回顾是每个 Sprint 的固定收尾活动，也是 Definition of Done 的一部分。

## 推荐时长

每轮约 30 至 45 分钟，根据 Sprint 内容调整。

## 固定结构

### 1. 交付结果

- 本轮解决了什么问题？
- 用户现在可以做什么？
- 哪些需求明确没有做？

### 2. 概念地图

- 本轮出现了哪些新概念？
- 它们分别解决什么问题？
- 它们之间如何连接？

### 3. 项目文件导览

- 哪些目录和文件发生了变化？
- 每个关键文件负责什么？
- 内容、样式、组件和配置分别放在哪里？

### 4. 最少必会操作

- 如何启动本地网站？
- 如何运行检查？
- 如何查看 Git 状态和当前分支？
- 本轮是否存在新的内容更新操作？

### 5. 关键决策

- 为什么采用当前方案？
- 放弃了哪些方案？
- 如果需求变化，哪里需要重新评估？

### 6. 小型知识检查

使用 3 至 5 个简短问题确认理解。重点是能用自己的话解释，不考查语法记忆。

### 7. 学习笔记

将回顾内容同步到 `E:\cs note`。项目仓库保存 Sprint Review，个人笔记目录保存学习副本。

## 掌握程度

每个概念使用三级标准：

- 认识：听到术语时知道它解决什么问题。
- 会用：能够按照说明完成常见操作。
- 深入：能够解释实现细节、排查异常或独立设计。

新手阶段默认目标是“认识 + 少量会用”，不要求每个概念都达到“深入”。

## 更新后的 Sprint 收尾流程

```text
功能与测试完成
→ Sprint Review
→ 学习回顾
→ 知识检查
→ Sprint Retrospective
→ 更新笔记和 Backlog
→ 关闭 Sprint
```
