# ADR-0002：采用 Astro 静态站点与 Supabase 托管后端

- 状态：Accepted
- 日期：2026-08-22

## 背景

Sprint 4 新增邮箱登录、个人资料、管理员权限、文章草稿、发布和图片。纯本地 Markdown 无法满足跨设备身份与动态数据需求，但项目仍不希望维护自建服务器。

## 决策

保留 Astro 静态输出和 GitHub Pages 托管；浏览器使用 Supabase JS 客户端连接 Supabase Auth、Postgres 和 Storage。前端只携带 publishable key，数据库写权限由 RLS、约束和受控函数保护。

## 结果

### 正面

- 不需要购买和维护云服务器。
- 静态页面继续快速、低成本部署。
- 身份、数据库、对象存储和事务邮件可使用托管能力。
- 权限规则与数据结构可通过 SQL 迁移追踪。

### 代价

- 网站动态功能依赖 Supabase 可用性和外部配置。
- Git 部署不会自动代表数据库迁移已经执行。
- 需要正确维护 RLS，错误规则可能造成越权或功能不可用。
- 静态内容与动态文章形成两种内容来源，搜索和维护需要进一步统一。

## 约束

- 禁止把 secret/service-role key 放入浏览器或 GitHub 公共源码。
- 新表默认启用 RLS，并为匿名、登录用户和管理员分别设计最小权限。
- 高权限操作优先使用受控数据库函数，并在函数内部再次验证管理员身份。
- 需要服务端秘密或后台任务时，另写 ADR 评估 Supabase Edge Functions 或独立后端。
